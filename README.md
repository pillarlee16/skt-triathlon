# SKT 철인3종 럭키드로우

Vite, TypeScript, Three.js와 Node.js를 사용하는 행사 운영 웹앱입니다. Railway의 영구 볼륨에 있는 SQLite 파일에 행사 상태와 사진·음원을 저장합니다. 개발 인수인계는 [PROGRESS.md](PROGRESS.md)를 확인하세요.

## 로컬 실행

Node.js 24에서 아래 명령을 실행한 뒤 Vite가 표시한 주소의 `/admin`을 여세요. 개발 서버 비밀번호는 `rehearsal`입니다. 개발 서버는 빈 명단으로 시작하고 종료하면 데이터가 초기화됩니다.

```sh
npm install
npm test
npm run typecheck
npm run build
npm run dev
```

운영 서버를 로컬에서 검증할 때는 `npm run build` 후 `DATA_DIR`, `ADMIN_PASSWORD`, 32자 이상의 `SESSION_SECRET`을 환경변수로 설정하고 `npm start`를 실행합니다. 기본 주소는 `http://127.0.0.1:3000`입니다. 운영 데이터를 저장소에 넣지 마세요.

## Railway 배포

1. GitHub 저장소의 `main` 브랜치를 기존 Railway 서비스에 연결합니다. Railpack의 빌드 명령은 `npm run build`, 시작 명령은 `npm start`, 헬스체크는 `/health`로 설정합니다. 서비스는 Node.js 24와 Railway가 주는 `PORT`를 사용합니다.
2. 서비스에 영구 볼륨 하나를 `/data`에 연결합니다. 서버는 볼륨이 없으면 시작하지 않습니다. SQLite는 `/data/triathlon.sqlite`에 상태와 파일을 함께 저장합니다.
3. Railway 서비스 변수에 `ADMIN_PASSWORD`와 32자 이상 무작위 `SESSION_SECRET`을 저장합니다. 공개 주소는 Railway가 제공하는 도메인을 사용하며, 다른 도메인으로 POST를 받을 경우 `PUBLIC_ORIGIN`을 그 HTTPS 주소로 지정합니다.
4. [운영 사이트](https://skt-luckydraw.up.railway.app/admin)에서 로그인하고 명단을 준비합니다. 실제 행사 전 Hobby로 올리고 가상 데이터와 현장 기기로 START·시상·CSV를 확인합니다. 볼륨이 붙은 서비스는 재배포 시 잠깐 중단될 수 있으므로 행사 중 배포를 피합니다.

## 행사 운영과 복구

1. `/admin`에서 로그인합니다. **참가자 준비**에서 이름을 한 명씩 추가하고 각 행에서 사진을 올립니다. 같은 이름이나 파일명도 각 행에 따로 연결됩니다. 사진을 생략하면 게임에서 기본 얼굴을 사용합니다.
2. 종목별 상품명을 저장합니다. 필요하면 **방송 설정**에서 상품 이미지, 포토월, 달리기 광고판, 로고, 사장님 얼굴, 음원과 경주 시간을 설정합니다. 이미지는 JPG·PNG·WebP, 음원은 MP3·WAV·OGG를 지원하며 파일당 변환 후 4 MB까지 등록할 수 있습니다. 권장 비율은 포토월 약 2.6:1, 광고판 약 6.7:1입니다.
3. **운영 전 준비**에서 참가자 수와 상품명 저장 상태를 확인합니다. 두 항목을 누르면 해당 입력란으로 이동합니다. 준비가 끝나면 **경기 운영으로**를 누르고 **TV 송출 열기**로 송출 창을 엽니다. TV 창에서 **음향 켜기**와 **전체 화면**을 선택한 뒤 관리자 화면의 연결 상태를 확인합니다. 태블릿은 **태블릿 리모컨 열기**가 가리키는 같은 사이트의 `/start` 주소를 사용합니다. 이 공개 주소에서 START를 누르면 서버가 그 시점에 준비된 경기를 시작합니다.
4. **START**로 추첨한 뒤 **시상식 시작**을 누릅니다. 3위·2위·1위 공개와 촬영이 끝나면 다음 종목으로 진행합니다. 첫 추첨 이후 준비 정보는 읽기 전용입니다. 행사가 끝나면 **CSV 다운로드**로 공식 결과를 받습니다.
5. 새로고침 또는 재로그인하면 기존 진행 단계로 돌아갑니다. 송출 창을 다시 열면 **음향 켜기**를 누르고 TV 연결을 확인합니다. **비상 진행**은 저장된 순위를 사용하며, 출발 전이라면 추첨 후 즉시 시상을 시작합니다. 연결이 지연되면 **같은 요청 재시도**를 사용합니다.
6. 결과를 정정하려면 **결과 및 복구**에서 종목과 재추첨 사유를 선택합니다. 해당 종목과 후속 종목의 결과가 이력에 보존되며 공식 CSV는 유효한 결과만 포함합니다.

Railway에는 행사 상태 하나가 있고, 로컬 개발 서버와 데이터가 분리됩니다. SQLite에 기록된 결과와 에셋은 서버나 컨테이너가 재시작돼도 연결한 볼륨에 남습니다.

신규 세션 기본 경주 시간은 종목별 40초입니다. 기존 세션의 저장된 설정은 유지되므로, 행사 전 승인된 운영 환경의 **방송 설정**에서 세 시간 값을 확인하세요. 경주 시간에는 출발 대기, 카운트다운, 시상이 포함되지 않습니다.

## 네트워크 장애 시 운영

- Railway 운영본은 브라우저에서 Railway에 접속해야 합니다. 행사 노트북에서 승인된 예비 네트워크로 같은 운영 URL에 재접속하고, 관리자 단계와 TV·음향 상태를 확인합니다.
- 가상 명단 로컬 리허설은 의존성을 미리 준비하면 인터넷 없이 같은 노트북에서 실행할 수 있습니다. `npm run dev`로 서버를 켜고 `http://127.0.0.1:5173/admin`과 TV 송출 창을 같은 브라우저 프로필에서 엽니다. 서버를 종료하면 이 리허설 상태가 초기화됩니다.
- 공식 추첨 중 연결이 끊기면 사회자가 진행을 잠시 보류하고, 운영자는 같은 운영 세션으로 재접속합니다. 이미 확정된 당첨자와 발표 단계를 확인하고 재개합니다. 같은 세션에 접속할 수 없으면 행사 책임자가 사전에 승인한 백업 절차를 적용합니다. 이미 추첨한 종목은 승인된 결과 사본으로만 이어가고, 당첨자가 확인될 때까지 해당 종목의 재추첨이나 이후 종목 추첨을 보류합니다. 로컬 가상 리허설은 송출 점검용으로 사용합니다.

## 현장 리허설

- 90명 얼굴 로딩과 선두 얼굴 식별, 1080p 두 TV 동일 송출과 30fps 목표를 확인합니다.
- 관리자·태블릿 동시 START, 경기 중 새로고침, 네트워크 재연결, 3D 장애 시 비상 발표를 확인합니다.
- 수영 → 사이클 → 달리기를 끝까지 진행해 9명 중복 여부, 결승·발표·CSV 일치, 재추첨 영향 범위를 확인합니다.
