# SKT 철인3종 럭키드로우

Vite, TypeScript, Three.js와 Vercel Functions를 사용하는 행사 운영 웹앱입니다. 본행사 추첨과 에셋은 Vercel Private Blob에 저장합니다. 개발 인수인계는 [PROGRESS.md](PROGRESS.md)를 확인하세요.

## 로컬 실행

Node.js 24에서 아래 명령을 실행한 뒤 Vite가 표시한 주소의 `/admin`을 여세요. 로컬 비밀번호는 `rehearsal`입니다. 로컬과 새 Preview 환경은 빈 명단으로 시작합니다. 로컬 데이터는 프로세스가 종료되면 초기화됩니다.

```sh
npm install
npm test
npm run typecheck
npm run build
npm run dev
```

## Vercel 배포

1. 승인된 Vercel 프로젝트에 이 폴더를 연결합니다. Framework Preset은 Vite, Node.js는 24.x, 빌드 명령은 `npm run build`, 출력 디렉터리는 `dist`입니다.
2. Production과 Preview 각각에 Private Blob 스토어를 연결해 환경별 `BLOB_READ_WRITE_TOKEN`을 제공합니다. 운영 비밀번호 `ADMIN_PASSWORD`와 32자 이상 무작위 값 `SESSION_SECRET`을 환경별로 설정합니다. 미리보기에는 가상 참가자만 사용합니다.
3. Preview에서 전체 리허설을 진행합니다. 본행사 데이터의 Vercel 사용에 대한 사내 승인을 확인한 뒤 Production에만 `APP_LIVE_ENABLED=true`를 설정하고 재배포합니다.
4. 운영 URL을 관리자와 태블릿에서 열어 로그인과 START 연동을 확인합니다. 배포 자체에 Vercel 접근 제한을 적용한 환경이라면 태블릿에서 해당 배포에 접근할 수 있게 설정합니다.

## 행사 운영과 복구

1. `/admin`에서 로그인합니다. **참가자 준비**에서 이름을 한 명씩 추가하고 각 행에서 사진을 올립니다. 같은 이름이나 파일명도 각 행에 따로 연결됩니다. 사진을 생략하면 게임에서 기본 얼굴을 사용합니다.
2. 종목별 상품명을 저장합니다. 필요하면 **방송 설정**에서 상품 이미지, 포토월, 달리기 광고판, 로고, 사장님 얼굴, 음원과 경주 시간을 설정합니다. 이미지는 JPG·PNG·WebP, 음원은 MP3·WAV·OGG를 지원하며 파일당 변환 후 4 MB까지 등록할 수 있습니다. 권장 비율은 포토월 약 2.6:1, 광고판 약 6.7:1입니다.
3. **운영 전 준비**에서 참가자 수와 상품명 저장 상태를 확인합니다. 두 항목을 누르면 해당 입력란으로 이동합니다. 준비가 끝나면 **경기 운영으로**를 누르고 **TV 송출 열기**로 송출 창을 엽니다. TV 창에서 **음향 켜기**와 **전체 화면**을 선택한 뒤 관리자 화면의 연결 상태를 확인합니다. 태블릿 시작 옵션은 현재 준비된 경기에서 30분 동안 유효합니다.
4. **START**로 추첨한 뒤 **시상식 시작**을 누릅니다. 3위·2위·1위 공개와 촬영이 끝나면 다음 종목으로 진행합니다. 첫 추첨 이후 준비 정보는 읽기 전용입니다. 행사가 끝나면 **CSV 다운로드**로 공식 결과를 받습니다.
5. 새로고침 또는 재로그인하면 기존 진행 단계로 돌아갑니다. 송출 창을 다시 열면 **음향 켜기**를 누르고 TV 연결을 확인합니다. **비상 진행**은 저장된 순위를 사용하며, 출발 전이라면 추첨 후 즉시 시상을 시작합니다. 연결이 지연되면 **같은 요청 재시도**를 사용합니다.
6. 결과를 정정하려면 **결과 및 복구**에서 종목과 재추첨 사유를 선택합니다. 해당 종목과 후속 종목의 결과가 이력에 보존되며 공식 CSV는 유효한 결과만 포함합니다.

운영 배포는 기존 운영 저장소를 사용하며, Preview의 가상 데이터와 로컬 데이터는 별도로 보관합니다. 새 주소에는 모드 선택이 필요 없습니다.

신규 세션 기본 경주 시간은 종목별 40초입니다. 기존 세션의 저장된 설정은 유지되므로, 행사 전 승인된 운영 환경의 **방송 설정**에서 세 시간 값을 확인하세요. 경주 시간에는 출발 대기, 카운트다운, 시상이 포함되지 않습니다.

## 네트워크 장애 시 운영

- Vercel 배포본은 브라우저에서 Vercel에 접속해야 하며, 서버는 Private Blob에 상태 및 에셋을 저장합니다. 행사 노트북에서 승인된 예비 네트워크로 같은 운영 URL에 재접속하고, 관리자 단계와 TV·음향 상태를 확인합니다.
- 가상 명단 로컬 리허설은 의존성을 미리 준비하면 인터넷 없이 같은 노트북에서 실행할 수 있습니다. `npm run dev`로 서버를 켜고 `http://127.0.0.1:5173/admin`과 TV 송출 창을 같은 브라우저 프로필에서 엽니다. 서버를 종료하면 리허설 상태가 사라지며, 현재 로컬 모드는 Vercel 운영 상태를 읽거나 복구할 수 없습니다.
- 공식 추첨 중 연결이 끊기면 사회자가 진행을 잠시 보류하고, 운영자는 같은 운영 세션으로 재접속합니다. 이미 확정된 당첨자와 발표 단계를 확인하고 재개합니다. 같은 세션에 접속할 수 없으면 행사 책임자가 사전에 승인한 백업 절차를 적용합니다. 이미 추첨한 종목은 승인된 결과 사본으로만 이어가고, 당첨자가 확인될 때까지 해당 종목의 재추첨이나 이후 종목 추첨을 보류합니다. 로컬 가상 리허설은 송출 점검용으로 사용합니다.

## 현장 리허설

- 90명 얼굴 로딩과 선두 얼굴 식별, 1080p 두 TV 동일 송출과 30fps 목표를 확인합니다.
- 관리자·태블릿 동시 START, 경기 중 새로고침, 네트워크 재연결, 3D 장애 시 비상 발표를 확인합니다.
- 수영 → 사이클 → 달리기를 끝까지 진행해 9명 중복 여부, 결승·발표·CSV 일치, 재추첨 영향 범위를 확인합니다.
